# v2.0.0 — an app you download and double-click

OpenStatsEngine 2.0 is an app. Download it, double-click it, and you are
running: no Node, no command line, no git. Everything since **v1.4.2**.

The stats engine, the entry screen and the vMix feeds are the same as 1.4.x. No
new vMix fields, no feed changes, nothing to re-bind. Your data carries over.

---

## Download

| | |
|---|---|
| **Windows** | `OpenStatsEngine-2.0.0-windows-x64.exe`. Double-click it. |
| **macOS** (Apple silicon and Intel) | `OpenStatsEngine-2.0.0-macos.zip`. Unzip, drag **OpenStatsEngine** into Applications, open it. |
| **Linux** | `OpenStatsEngine-2.0.0-linux-x64.tar.gz`. Run `./openstatsengine`. |

A console window opens, and that window is the server: leave it open during the
game, close it to stop. The entry page opens in your browser by itself.

**First launch asks you to trust it**, because the apps are not signed with a
paid developer certificate:

- **Windows:** *Windows protected your PC* → **More info** → **Run anyway**.
- **macOS:** right-click the app in Applications → **Open** → **Open**. On
  macOS 15 and later: try to open it once, then **System Settings → Privacy &
  Security → Open Anyway**.

Running from a git checkout still works exactly as before.

## Bringing your data over

The app keeps data in `Documents/OpenStatsEngine`. To bring a 1.4 season with
you, either:

- **Setup → Data Folder**: point it at your existing `data` folder (or wherever
  you keep it) and restart. A folder with data in it is used as it is.
- or copy the `data` folder into `Documents` and rename it `OpenStatsEngine`.

## Keep your data in Google Drive

**Setup → Data Folder** chooses where teams, rosters and games live. Point it at
a Google Drive, OneDrive or Dropbox folder and the season syncs to the cloud as
you go.

- **Check Folder** says what is there first ("2 teams, 14 games"), and
  existing data is never copied over.
- **Copy** brings your current data into a new, empty folder.
- If the folder is missing at startup (Drive not running yet), OpenStatsEngine
  waits up to 30 seconds for it, then stops and tells you, rather than starting
  on an empty folder and splitting your season in two.

Run one computer at a time against a synced folder.

## It tells you when there is an update

At startup OpenStatsEngine checks GitHub once. When a newer release is out, a
green **⬆** link appears in the top bar, pointing at the download. Offline, it
stays quiet.

**Setup → Updates** picks the channel:

- **Stable**: finished releases only. This is the default, and what you want
  on game nights.
- **Beta**: test versions too, ahead of release.

Git checkouts get it from the start scripts instead, which offer to update
*(Update now? [y/N])* and start the current version after 15 seconds with no
answer.

## Also

- **Position tabs on the player picker**: All, QB, RB, WR… above the jersey
  grid, remembered per field. This came in 1.4.2.
- **An icon** for the apps, the browser tab and a tablet's home screen. On
  Windows the `.exe` says *OpenStatsEngine* in Properties and Task Manager.
- The console and `/api/config` report the real version. `/api/config` had
  said `1.1.0` since 1.1.0.
- The vMix tab shows the real path of the XML files.
- New in the manual: **Updating**, **Stable or beta**, **Data folder**, and a
  table of command-line options. The apps take the same options as
  `node server.js`.
